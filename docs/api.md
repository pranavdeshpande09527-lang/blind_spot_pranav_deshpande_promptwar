# Canonical API contract

All /api routes except /api/config require a verified Supabase bearer token. JSON success responses use {data: ...}; failures use {error:{code,message,requestId}}. Never accept user_id, provider credentials or run status from the browser. All IDs are UUIDs. Ownership failures return 404. Return 400 validation, 401 authentication, 409 revision/idempotency conflict, 429 throttling, 502 invalid/unavailable provider and 504 deadline exceeded as appropriate. A failed analysis response may include error.analysisId for retry/status lookup.

Implementation notes: `/api/config` also returns `analysisAvailable` and `setupRequired` based on configuration presence, not live provider health. Infrastructure/setup failures return 503; oversized bodies return 413 and denied origins return 403. Unknown API paths return JSON 404. PATCH supplies all editable fields plus expectedRevision (full replacement of editable input). Reflection reads are capped at 200 records; snapshots include the 16 latest updated answers. Analysis envelopes contain persisted `questions`. OpenAPI is generated by `npm run build`; route inventory is checked by tests.

| Method and route | Request | Response |
| --- | --- | --- |
| GET /healthz | none | 200 {status:"ok"}; no paid calls, secrets or database narratives |
| GET /api/config | none | public Supabase URL/key and {researchAvailable,fallbackAvailable}; no provider keys |
| POST /api/decisions | decision fields from contracts.md | 201 persisted Decision |
| GET /api/decisions?limit=20&cursor=... | limit 1–50; opaque validated cursor | {items,nextCursor} owned newest-first history |
| GET /api/decisions/:id | none | owned Decision |
| PATCH /api/decisions/:id | expectedRevision plus editable fields | updated Decision, revision incremented atomically |
| DELETE /api/decisions/:id | none | 200 {deleted:true}; cascade children |
| POST /api/decisions/:id/analyses | {expectedRevision}; required Idempotency-Key header UUID | 201 completed Analysis; matching completed replay 200; matching processing replay 202 |
| GET /api/decisions/:id/analyses | optional limit/cursor | {items,nextCursor} owned analysis summaries |
| GET /api/decisions/:id/analyses/:analysisId | none | full Analysis, output and sources, or processing/failed state |
| GET /api/decisions/:id/analyses/by-key/:key | none | matching run or 404; register before dynamic analysisId route |
| GET /api/decisions/:id/reflections | none | saved reflection answers |
| PUT /api/decisions/:id/reflections/:questionId | {analysisId,answer,expectedRevision} | {reflection,decisionRevision}; transactional upsert and revision increment |

Decision fields: decision, context, options, reasons, constraints, affected, deadline (all text), researchEnabled (boolean). Require decision and context or reasons. Preserve field naming from the existing HTML; do not turn options into an incompatible array or deadline into a mandatory timestamp.

Analysis: id, decision_id, input_revision, status, created_at, started_at, completed_at, expires_at, actual provider/model when used, research_status, output (only on completion), sources and safe error_code. Internal snapshots can be returned to the owner when viewing historical runs. Never display processing output as completed.

Idempotency keys are unique per owner/decision and associated with input revision. Same key/different revision is 409. Failed runs stay failed and a deliberate retry uses a new key. A distinct key while an active run exists returns 409 with that run ID. Use database constraints/RPCs for atomic behavior, not just process memory. Expire stale processing runs atomically before permitting new runs.

Reflection questionId is a server-assigned stable ID attached to an analysis question. Validate that analysis, question, decision and owner match before saving. Updating an answer increments decision revision so old output is marked stale. Research opt-in changes also increment revision.
